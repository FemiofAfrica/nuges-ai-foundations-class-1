2. Exercise: test knowledge of the concepts

Answer first, then open each short answer key.

Prompt card: new analogy

Explain MCP with a different biology analogy. Map roles, give one NUGES example, and state one limitation. Do not describe AI as alive.
Answer key

MCP discovers and uses approved tools or context providers. It is not the model, training, or a guarantee of accuracy or permission.

Scenario cards: missing layers

  • Generic ideas despite “sound like NUGES”.
  • Cannot retrieve the current brief.
  • Publishes a draft immediately.
  • Uses a retired voice rule.
Answer key

Context, retrieval/API permission, guardrails and human approval, and memory or feedback respectively.

Model versus full system

Name four layers around the model that make a NUGES result useful and safe.

Answer key

Prompt, context, memory, harness, tools, interfaces, permissions, feedback, and guardrails are acceptable.

Context, memory, API, MCP, WebSockets, gates

Define each operationally and classify draft, retrieve, send, publish, and confidential-data actions.

Answer key

Context is needed now; memory is deliberately retained. API requests data or action; MCP discovers approved tools or context; WebSockets carry persistent two-way messages. Draft and approved retrieval may be allowed; send and publish require human approval; unapproved confidential use is prohibited. None proves accuracy.

3. Prompt Engineering versus Context Engineering

Prompt

The immediate instruction for this task.

Context

The surrounding information environment: sources, facts, current state, rules, permissions, memory, tools, and review.

Prompt wording cannot replace missing NUGES knowledge. Context reduces repeated explanation. Neither changes model weights. Weight updates require separate training or fine-tuning.

Bare prompt

Give me five social media campaign ideas for NUGES.

Improved with verified facts

Use only verified public descriptions from nugesmedia.com and nugesmedia.com/meet-nugesmedia/. Draft three ideas with audience, purpose, hook, and source basis. Do not invent services, clients, results, prices, staff, or claims. Mark gaps [NUGES TO CONFIRM]. Draft only.

Short prompt using reusable shared context

Using the shared NUGES organizational context and approved public sources, draft three low-risk content ideas. Show source basis and [NUGES TO CONFIRM] gaps. Draft only. Do not publish or invent facts.
Before and after

Before: generic assumptions and no approval boundary. After: reusable verified facts, evidence labels, constraints, and review expectations surround a shorter request.

FACILITATOR PROMPT CARDS
1. Choose a low-risk task, audience, outcome, data boundary, reviewer, approval gate, and done definition.
2. Ask who NUGES is, what it does, who it serves, and what outcomes are supported.
3. Capture voice, prohibited claims or actions, and approved examples.
4. Map workflows, handoffs, tools, stopping points, and decision rules.
5. Classify data categories, permissions, and human approval.
6. Assign ownership, source of truth, freshness, review dates, and open questions.
7. Assemble the accepted cards into the working shared NUGES organizational context engine.
8. Test, diagnose one failing layer, revise one variable, and inspect again.
