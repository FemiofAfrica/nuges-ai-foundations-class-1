03 · Prompt engineering versus context engineering

3. Prompt Engineering versus Context Engineering

Prompt engineering shapes the request. Context engineering shapes the working situation around the request.

Prompt only

A message enters the model. A generic output leaves.

“Do this now”→MODEL→generic output
Context loaded

Facts, examples, constraints, memory, and permissions circulate around the model.

factsrulesmemory→situated output

Pass 1 · bare prompt

Give me five social media campaign ideas for NUGES.

Pass 2 · verified facts

You are helping with a low-risk draft for NUGES Media. Use only supplied verified public facts. Draft three content ideas for prospective clients. Do not invent services, clients, results, prices, staff, or claims. Mark missing facts [NUGES TO CONFIRM]. Draft only.

Pass 3 · shared context

Using the shared NUGES organizational context and approved public sources, draft three low-risk content ideas for prospective clients. Show source basis and [NUGES TO CONFIRM] gaps. Draft only. Do not publish or invent facts.

Supplying context changes what the system sees for this work. It does not update model weights.

04 · Practical collaborative build
SHARED NUGES CONTEXT

4. Practical: build NUGES MEDIA & ADVERTISING's organizational context engine together

Empty state: Add approved context. Each accepted item needs evidence label, source, owner, sensitivity, permission, review date, and unresolved question.

Anchor prompt

We are co-building a shared NUGES organizational context engine. Use verified public sources or authorized statements. Label every item Verified public, Authorized internal, Proposed, or [NUGES TO CONFIRM]. Never infer facts, permissions, or approval owners.

Room prompt

Ask the room to choose one real, low-risk NUGES task. Record audience, objective, allowed data, prohibited data, reviewer, approval gate, and definition of done. Mark unknown fields [NUGES TO CONFIRM].
05 · Assignment

5. Assignment: build your own personal context engine

Hand off from the collective body to your own context engine.

  1. Choose one recurring task.
  2. Identify the context it needs.
  3. Define one review or approval boundary.

Personal sequence

Interview me about my role, responsibilities, goals, recurring tasks, audiences, preferences, outputs, quality rules, privacy boundaries, decision rules, and one low-risk test task. Ask, do not guess. Keep organization-wide unknowns [NUGES TO CONFIRM]. Assemble my personal context engine v1 and ask me to correct anything untrue before saving.
