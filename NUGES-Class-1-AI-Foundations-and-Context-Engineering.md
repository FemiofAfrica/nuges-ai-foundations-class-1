# NUGES MEDIA & ADVERTISING
## Class 1: AI Foundations and Context Engineering

**Format:** 3-hour facilitator-led workshop  
**Facilitator:** Femi  
**Primary workspace:** One private Notion teamspace, or an approved equivalent  
**Audience:** NUGES participants working in creative, production, strategy, operations, research, or client work  
**Class 2 dependency:** Participants leave with a tested personal context engine and a shared NUGES organizational context system to extend.

> **Evidence rule:** Use only the public facts listed in this plan or facts supplied and authorized during class. Mark missing, proposed, or unverified organization-specific information as `[NUGES TO CONFIRM]`. Never turn a plausible assumption into a NUGES fact.

---

## 1. Class promise and outcomes

By the end of the class, each participant can:

1. Explain the biology-to-AI operating model: a capable model needs a body, environment, memory, tools, feedback, and constraints to perform useful work.
2. Distinguish a model from a full AI system.
3. Define and locate the harness, prompt, context, memory, API, MCP, WebSockets, tools, feedback loops, and guardrails.
4. Co-build one shared NUGES organizational context system containing evidence, institutional knowledge, operating rules, permissions, and approval gates.
5. Build a personal context engine that references the shared NUGES system and adds role, responsibilities, preferences, goals, recurring tasks, output formats, and personal quality rules.
6. Test the shared NUGES context against one real, low-risk NUGES task, then revise from observed evidence.
7. Apply data governance and permissions before placing information into shared or personal context.

### Success evidence

The class is successful when the room has produced:

- A private shared workspace for NUGES context work. Public publishing is disabled.
- A NUGES organizational context index with source status, owner, sensitivity, permission, review date, and AI use.
- A verified public-facts page and a separate `[NUGES TO CONFIRM]` discovery register.
- A proposed organizational voice card, audience card, services map, workflow map, constraints list, examples register, decision rules, data boundaries, and approval gates, each with evidence status.
- A shared low-risk NUGES task brief and a three-pass test record.
- One personal context engine per participant, linked to shared NUGES context without copying restricted information.
- An assessment record and Class 2 homework commitment.

## 3. Non-negotiable framing

### The biology-to-AI operating model

Use the body as a systems analogy, not as a claim that AI is alive:

| Biology analogy | AI system layer | Workshop meaning |
|---|---|---|
| Brain | Model | Generates and transforms patterns, but does not automatically know NUGES. |
| Nervous system | Harness and API | Carries instructions, state, permissions, and results between parts. |
| Senses | Context and retrieval | Supplies relevant public facts, approved internal facts, documents, examples, and current state. |
| Long-term memory | Memory store | Preserves approved NUGES facts, preferences, decisions, and history for later use. |
| Hands and organs | Tools | Performs approved actions such as search, calculation, file work, or record lookup. |
| Reflex and learning | Feedback loops | Tests output, observes failure, and updates the next attempt. |
| Skin, immune system, ethics | Guardrails | Limits unsafe, unauthorized, private, or misleading behavior. |
| Environment | Workspace and workflow | Determines what the system can access and what counts as a valid result. |

**Facilitator script:** “A model is the brain-like component. Useful NUGES AI work comes from the whole operating system around it. Today we will build that surrounding system before we ask for clever output.”

### Model versus full system

- **Model:** The learned prediction or generation engine.
- **Full system:** Model plus harness, prompt, context, memory, tools, interfaces, permissions, feedback, and guardrails.
- **Operating model:** The repeatable pattern for giving an AI system the right NUGES information, authority, workflow, and review at the right time.

### Component glossary

| Component | Plain definition | NUGES class application |
|---|---|---|
| Harness | Wrapper that manages instructions, context assembly, state, tools, permissions, and output handling. | A private NUGES workspace assembles a brief, approved sources, and a review checklist. |
| Prompt | The immediate task request and instructions. | Ask for a public NUGES positioning summary in a specified format. |
| Context | Relevant information supplied for this task. | Public facts, authorized internal facts, audience, objective, constraints, examples, and source links. |
| Memory | Information intentionally retained across tasks. | An approved NUGES glossary, decision record, or recurring quality rule. |
| API | A programmatic interface for one system to request data or action from another. | An approved workflow requests a current NUGES brief from a connected system. |
| MCP | An AI-oriented connection pattern for discovering and using approved tools and context providers. | An approved NUGES AI workspace connects to a knowledge source or action tool. |
| WebSockets | A persistent two-way connection for near-real-time messages. | A live collaboration surface could stream status when that use is approved. |
| Tools | Callable capabilities that retrieve information or perform an action. | Search, document lookup, calculation, or an approved record action. |
| Feedback loop | Request, result, evaluation, diagnosis, and revision. | Compare a draft to NUGES sources and revise the context or rule. |
| Guardrails | Human and technical controls that constrain behavior and data use. | No unsupported NUGES claims, no restricted data in an unapproved tool, and approval before external use. |

**Teaching note:** MCP is not the same thing as an API, and WebSockets are not a replacement for either. API describes an interface. MCP describes an AI-oriented connection pattern for tools and context. WebSockets describe a live transport pattern.

## 7. Practical Part A: co-build one shared NUGES organizational context system

### 01:15 to 01:40 | Discover, separate, and validate

Femi facilitates a structured capture round. First collect candidate items without polishing them. Then classify each item. Finally validate what can be validated in the room.

#### Discovery prompts

Ask the room and the authorized NUGES representative:

1. **Identity and voice:** “How should NUGES sound in internal and external work? Which words, tones, and claims are preferred or avoided?”
2. **Audiences:** “Who are the audiences for this task? Which audience distinctions are verified, and which need confirmation?”
3. **Services:** “Which NUGES services may we name? What is the boundary of each service? What remains unknown?”
4. **Workflows:** “What triggers the work, what inputs are required, what handoffs occur, what is the definition of done, and where does work stop for review?”
5. **Constraints:** “What legal, brand, accessibility, channel, timing, budget, or client constraints apply? Which are documented?”
6. **Examples:** “Which approved NUGES examples can teach the desired output? Who authorized their use?”
7. **Decision rules:** “Who decides when facts conflict, when scope changes, or when a claim is ready for external use?”
8. **Data boundaries:** “What may the system retrieve, what may it draft from, what may it retain, and what must never be entered?”
9. **Approval gates:** “Which outputs are drafts only, which need named human review, and which actions are prohibited for AI?”

#### Evidence labels

- `Verified public`: supported by the two supplied public sources or another public source checked during class.
- `Authorized internal`: supplied by an authorized NUGES representative or approved internal material, with source and owner recorded.
- `Proposed`: a workshop design suggestion, not current NUGES policy.
- `[NUGES TO CONFIRM]`: missing, disputed, or not authorized for confirmation in this class.

**Do not infer:** If a service, value, audience, workflow, example, rule, permission, or approval owner is not supported, leave it unverified.

## 10. Data governance and permissions

Apply these rules to the shared NUGES system, every personal engine, and every AI tool used in class.

### Information categories

- **Public:** Safe for public-source context when the source is recorded.
- **Internal:** For approved NUGES participants and tools only.
- **Confidential:** Restricted to named people or groups with a specific business need.
- **Restricted:** Do not place in the class workspace or an AI tool unless an explicit approved process permits it.

### Permission verbs

Record the exact permission for each context item:

- `retrieve`: AI may find and quote or summarize it for an approved task.
- `draft from`: AI may use it to prepare a draft, subject to human review.
- `retain`: The system may keep it as memory until review or expiry.
- `action support`: AI may prepare an action but not execute it without the named gate.
- `prohibited`: Do not use in this context or tool.

### Non-negotiable controls

- Never enter passwords, API keys, payment details, identity numbers, health information, or restricted client material into an unapproved tool.
- Do not treat generated text as a source. Label unknowns and verify important claims.
- Separate drafting permission from sending, publishing, deleting, buying, or changing records.
- Use least privilege for integrations, APIs, MCP servers, WebSocket channels, and action tools.
- Keep personal context private unless the owner explicitly authorizes sharing.
- Do not store sensitive personal details merely because they could improve personalization.
- Record source, owner, status, sensitivity, permission, and review date for NUGES organizational memory.
- Require human approval for external claims, client commitments, publication, regulated content, disclosure of confidential material, and irreversible actions.
- Remove stale or unnecessary memory and record the reason for material changes.

### Stop conditions

Pause and escalate when a participant cannot identify the source, owner, sensitivity, permission, or approver for a proposed item. Pause when a request asks the AI to publish, send, delete, purchase, commit, or disclose without a named human gate. `[NUGES TO CONFIRM]` is a valid result. Guessing is not.
